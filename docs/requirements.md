## 0. 개요

### 0.1 서비스 요약

누구나 글을 읽고, 가입한 사용자는 글·댓글·좋아요로 참여하는 모바일 웹 커뮤니티.
하단 탭은 **홈(피드) · 내정보(프로필) · 설정** 3개로 구성한다.

### 0.2 사용자 구분

| 구분 | 설명 | 할 수 있는 일 |
| --- | --- | --- |
| 비회원 | 로그인하지 않은 방문자 | 글 목록·상세·댓글 열람, 다른 유저 프로필 열람, 회원가입, 로그인 |
| 회원 | 로그인한 사용자 | 비회원 권한 + 글 작성, 댓글 작성, 좋아요, 내 프로필 수정, 로그아웃 |

### 0.3 범위

**포함**: 회원가입 / 로그인 / 로그아웃, 글 작성·목록·상세, 댓글, 좋아요, 프로필(닉네임·프로필 이미지·내가 쓴 글), 다른 유저 프로필 보기

**제외 (이번 버전에서 만들지 않음)**: 글·댓글 수정/삭제, 글 이미지 첨부, 대댓글, 댓글 좋아요, 소셜 로그인, 비밀번호 재설정, 회원 탈퇴, 검색, 알림, 팔로우, 신고·차단, 관리자 기능

> 요청에 명시되지 않은 부분은 가정으로 채웠다. 가정 목록은 [6. 확인이 필요한 가정](#6-확인이-필요한-가정)에 모아 두었다.

## 2. 기능 상세 요구사항

### 2.1 인증

#### AUTH-01 회원가입

- **입력 항목**

  | 항목 | 규칙 |
  | --- | --- |
  | 이메일 | 이메일 형식, 가입된 이메일과 중복 불가 |
  | 비밀번호 | 8자 이상 |
  | 비밀번호 확인 | 비밀번호와 일치 |
  | 닉네임 | 2~12자, 한글·영문·숫자·밑줄(_)만 허용, 다른 회원과 중복 불가 |

- **동작**
  1. 모든 항목이 규칙을 만족해야 가입 버튼이 활성화된다.
  2. 가입에 성공하면 프로필(닉네임, 기본 프로필 이미지)이 함께 생성된다.
  3. 가입 직후 자동으로 로그인된 상태가 되어 홈으로 이동한다. (이메일 인증 절차 없음)
- **예외 처리**
  - 이미 가입된 이메일: "이미 가입된 이메일입니다."
  - 닉네임 중복: "이미 사용 중인 닉네임입니다."
  - 규칙 위반: 해당 입력란 아래에 사유를 표시한다.
  - 로그인 상태에서 회원가입 화면에 접근하면 홈으로 보낸다.

#### AUTH-02 로그인

- **입력 항목**: 이메일, 비밀번호
- **동작**
  1. 로그인에 성공하면 직전에 하려던 화면으로 돌아간다. 돌아갈 곳이 없으면 홈으로 이동한다.
  2. 브라우저를 닫았다 열어도 로그인 상태가 유지된다.
  3. 로그인 화면에서 회원가입 화면으로 이동할 수 있다.
- **예외 처리**
  - 인증 실패: "이메일 또는 비밀번호가 올바르지 않습니다." (어느 쪽이 틀렸는지는 알려주지 않는다.)
  - 로그인 상태에서 로그인 화면에 접근하면 홈으로 보낸다.

#### AUTH-03 로그아웃

- 설정 탭의 로그아웃 버튼으로 실행한다.
- 버튼을 누르면 확인 창("로그아웃 하시겠어요?")을 띄우고, 확인 시 세션을 종료한 뒤 홈으로 이동한다.

#### 로그인이 필요한 동작의 공통 규칙

- 비회원이 로그인 필요 동작(글쓰기, 댓글 작성, 좋아요, 내정보 탭)을 시도하면 로그인 화면으로 안내한다.
- 로그인을 마치면 원래 있던 화면으로 되돌아온다.

### 2.2 글

#### POST-01 글 작성

- **진입**: 홈 화면 우측 하단의 글쓰기 버튼(플로팅 버튼)
- **입력 항목**

  | 항목 | 규칙 |
  | --- | --- |
  | 제목 | 1~100자 |
  | 본문 | 1~5,000자, 텍스트만 (줄바꿈 유지) |

- **동작**
  1. 제목과 본문이 모두 입력되어야 등록 버튼이 활성화된다.
  2. 등록에 성공하면 방금 쓴 글의 상세 화면으로 이동한다.
  3. 등록 처리 중에는 버튼을 비활성화해 중복 등록을 막는다.
- **예외 처리**
  - 등록 실패: 입력 내용을 유지한 채 오류 메시지를 표시한다.
  - 입력 내용이 있는 상태에서 뒤로 가면 "작성 중인 내용이 사라집니다" 확인 창을 띄운다.

#### POST-02 글 목록 (피드)

- **정렬**: 최신순 (작성 시각 내림차순)
- **페이지 처리**: 20개씩 불러오며, 목록 끝에 도달하면 다음 20개를 이어서 불러온다. (무한 스크롤)
- **목록 항목에 표시할 정보**
  - 작성자 프로필 이미지, 닉네임
  - 제목 (1줄, 넘치면 말줄임)
  - 본문 미리보기 (2줄, 넘치면 말줄임)
  - 작성 시각 (상대 시간: "방금 전", "5분 전", "3시간 전", 7일이 지나면 날짜)
  - 좋아요 수, 댓글 수
- **동작**
  - 항목을 누르면 글 상세로 이동한다.
  - 작성자 프로필 이미지·닉네임을 누르면 해당 유저의 프로필로 이동한다.
  - 상세에서 목록으로 돌아오면 이전 스크롤 위치를 유지한다.
- **상태 표시**
  - 불러오는 중: 스켈레톤
  - 글이 없음: "아직 글이 없어요. 첫 글을 남겨보세요."
  - 불러오기 실패: 오류 메시지와 다시 시도 버튼

#### POST-03 글 상세

- **표시할 정보**: 제목, 본문 전체, 작성자(프로필 이미지·닉네임), 작성 시각, 좋아요 버튼과 좋아요 수, 댓글 수, 댓글 목록, 댓글 입력창
- **동작**
  - 작성자를 누르면 해당 유저의 프로필로 이동한다.
  - 상단 뒤로가기로 이전 화면으로 돌아간다.
- **예외 처리**
  - 존재하지 않는 글: "글을 찾을 수 없습니다" 안내와 홈으로 가는 버튼을 표시한다.

### 2.3 댓글

#### CMT-01 댓글 목록

- 글 상세 화면의 본문 아래에 표시한다.
- **정렬**: 작성순 (오래된 댓글이 위)
- **항목 정보**: 작성자 프로필 이미지·닉네임, 내용, 작성 시각
- 작성자를 누르면 해당 유저의 프로필로 이동한다.
- 댓글이 없으면 "첫 댓글을 남겨보세요."를 표시한다.
- 댓글에 대한 답글(대댓글)은 지원하지 않는다.

#### CMT-02 댓글 작성

- **입력 규칙**: 1~500자, 텍스트만
- **동작**
  1. 글 상세 화면 하단에 고정된 입력창에서 작성한다.
  2. 등록에 성공하면 목록 맨 아래에 바로 추가되고 입력창이 비워지며, 댓글 수가 갱신된다.
  3. 등록 처리 중에는 버튼을 비활성화한다.
- **비회원**: 입력창 자리에 "로그인하고 댓글 쓰기"를 표시하고, 누르면 로그인 화면으로 이동한다.

### 2.4 좋아요

#### LIKE-01 좋아요 / 취소

- 대상은 글이다. (댓글에는 좋아요가 없다.)
- 한 회원은 한 글에 좋아요를 한 번만 할 수 있다. 다시 누르면 취소된다.
- 좋아요 버튼은 글 상세 화면에 있다. 피드에서는 좋아요 수만 표시한다.
- 본인이 쓴 글에도 좋아요를 누를 수 있다.
- 누르는 즉시 버튼 상태와 숫자를 바꾸고, 서버 처리에 실패하면 원래 상태로 되돌린다.
- 내가 좋아요한 글은 버튼이 채워진 상태로 표시된다.
- 비회원이 누르면 로그인 화면으로 안내한다.

### 2.5 프로필

#### PROF-01 내 프로필 보기

- **진입**: 하단 탭의 내정보
- **표시할 정보**: 프로필 이미지, 닉네임, 작성한 글 수, 프로필 수정 버튼, 내가 쓴 글 목록
- **내가 쓴 글 목록**: 최신순, 20개씩 무한 스크롤. 항목 구성은 피드와 같다. 누르면 글 상세로 이동한다.
- 쓴 글이 없으면 "아직 작성한 글이 없어요."를 표시한다.
- **비회원**: 프로필 대신 로그인 안내와 로그인·회원가입 버튼을 표시한다.

#### PROF-02 프로필 수정

- **진입**: 내정보 화면의 프로필 수정 버튼
- **수정 가능 항목**

  | 항목 | 규칙 |
  | --- | --- |
  | 닉네임 | 회원가입과 동일 (2~12자, 한글·영문·숫자·밑줄, 중복 불가) |
  | 프로필 이미지 | JPG · PNG · WebP, 5MB 이하. 원형으로 잘라서 표시 |

- **동작**
  1. 이미지를 고르면 저장 전에 미리보기를 보여준다.
  2. 프로필 이미지를 삭제하면 기본 이미지로 돌아간다.
  3. 저장에 성공하면 내정보 화면으로 돌아가고, 변경 내용이 서비스 전체(피드, 글 상세, 댓글)에 반영된다.
- **예외 처리**
  - 닉네임 중복, 파일 형식·용량 초과 시 사유를 표시하고 저장하지 않는다.
  - 이메일은 이 화면에서 변경할 수 없다.

#### PROF-03 다른 유저 프로필 보기

- **진입**: 피드·글 상세·댓글에서 작성자의 프로필 이미지 또는 닉네임을 누른다.
- **표시할 정보**: 프로필 이미지, 닉네임, 작성한 글 수, 그 유저가 쓴 글 목록 (최신순, 20개씩 무한 스크롤)
- 프로필 수정 버튼은 표시하지 않는다.
- 이메일 등 계정 정보는 노출하지 않는다.
- 본인의 프로필 주소로 들어온 경우 내정보 화면으로 보낸다.
- 존재하지 않는 유저: "사용자를 찾을 수 없습니다" 안내를 표시한다.

### 2.6 공통 · 설정

#### NAV-01 하단 탭

- 탭 구성: **홈** · **내정보** · **설정** (왼쪽부터)
- 화면 하단에 고정하며, 현재 탭을 강조 표시한다.
- 탭의 첫 화면(홈, 내정보, 설정)에만 표시한다. 그 외 화면(글 상세, 글 작성, 로그인 등)에서는 숨기고 상단에 뒤로가기 버튼을 둔다.
- 현재 탭을 다시 누르면 화면 맨 위로 스크롤한다.

#### SET-01 설정

- **회원**: 로그인한 계정의 이메일, 로그아웃 버튼, 앱 버전
- **비회원**: 로그인 버튼, 앱 버전

### 2.7 비기능 요구사항

| 구분 | 요구사항 |
| --- | --- |
| 화면 | 모바일 우선. 기준 폭 360~430px. 넓은 화면에서는 최대 폭 480px로 가운데 정렬 |
| 터치 | 버튼·탭 등 누르는 영역은 최소 44×44px |
| 기기 대응 | 하단 탭과 댓글 입력창은 기기 하단 안전 영역(safe area)을 침범하지 않는다 |
| 언어 | 한국어 |
| 보안 | 모든 테이블에 RLS 적용. 작성자 정보는 클라이언트 입력이 아닌 로그인 세션 기준으로 결정 |
| 피드백 | 모든 요청에 대해 처리 중·성공·실패 상태를 화면에 표시 |
| 배포 | Vercel. Supabase 접속 정보는 환경변수로 관리 |

## 3. 사용자 흐름

### 3.1 회원가입 후 첫 글 작성

1. 홈 진입 (비회원 상태로 피드 열람)
2. 글쓰기 버튼 누름 → 로그인 화면으로 안내
3. "회원가입" 누름 → 회원가입 화면
4. 이메일·비밀번호·닉네임 입력 후 가입 → 자동 로그인, 홈으로 이동
5. 글쓰기 버튼 누름 → 글 작성 화면
6. 제목·본문 입력 후 등록 → 글 상세 화면

### 3.2 로그인

1. 로그인 화면 진입 (내정보 탭, 설정 탭, 또는 로그인 필요 동작에서 안내)
2. 이메일·비밀번호 입력 후 로그인
3. 성공 → 직전 화면으로 복귀 (없으면 홈) / 실패 → 오류 메시지 표시 후 재입력

### 3.3 글 읽기 · 좋아요 · 댓글

1. 홈에서 피드 스크롤 (끝에 도달하면 다음 글 자동 로드)
2. 글 항목 누름 → 글 상세
3. 좋아요 버튼 누름 → 즉시 반영 (비회원이면 로그인 안내)
4. 댓글 입력 후 등록 → 댓글 목록 맨 아래에 추가 (비회원이면 로그인 안내)
5. 뒤로가기 → 피드의 이전 스크롤 위치로 복귀

### 3.4 다른 유저 프로필 보기

1. 피드, 글 상세, 댓글 중 한 곳에서 작성자의 프로필 이미지 또는 닉네임 누름
2. 해당 유저 프로필 화면 (본인이면 내정보 화면으로 이동)
3. 그 유저가 쓴 글 누름 → 글 상세
4. 뒤로가기 → 이전 화면

### 3.5 프로필 수정

1. 하단 탭 내정보 → 프로필 수정 버튼
2. 닉네임 수정 또는 프로필 이미지 선택 (미리보기 확인)
3. 저장 → 내정보 화면으로 복귀, 변경 내용 반영

### 3.6 로그아웃

1. 하단 탭 설정 → 로그아웃 버튼
2. 확인 창에서 확인 → 세션 종료, 홈으로 이동 (비회원 상태)

### 3.7 화면 이동 구조

```
[하단 탭]
 ├─ 홈(피드) ──┬─ 글 상세 ──┬─ 다른 유저 프로필 ── 글 상세
 │             │            └─ (비회원) 로그인
 │             ├─ 글 작성 ── 글 상세
 │             └─ 다른 유저 프로필
 ├─ 내정보 ────┬─ 프로필 수정
 │             ├─ 글 상세
 │             └─ (비회원) 로그인 ── 회원가입
 └─ 설정 ──────┬─ 로그아웃 → 홈
               └─ (비회원) 로그인
```

## 5. 데이터 개요

### 5.1 관계

```
auth.users (Supabase 관리)
    │ 1:1
profiles ──┬── 1:N ── posts ──┬── 1:N ── comments
           │                  └── 1:N ── likes
           ├── 1:N ── comments
           └── 1:N ── likes
```

### 5.2 테이블

#### profiles — 회원 프로필

| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| id | uuid (PK) | `auth.users.id`와 동일 |
| nickname | text, unique, not null | 닉네임 |
| avatar_url | text, nullable | 프로필 이미지 주소. 비어 있으면 기본 이미지 표시 |
| created_at | timestamptz | 가입 시각 |
| updated_at | timestamptz | 수정 시각 |

- 회원가입 시 계정과 함께 자동 생성된다.
- 이메일·비밀번호는 Supabase Auth가 관리하며 이 테이블에 두지 않는다.

#### posts — 글

| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| id | uuid (PK) | 글 ID |
| author_id | uuid (FK → profiles.id) | 작성자 |
| title | text, not null | 제목 (1~100자) |
| content | text, not null | 본문 (1~5,000자) |
| created_at | timestamptz | 작성 시각 |

- 피드 정렬과 프로필의 글 목록을 위해 `created_at`, `author_id`에 인덱스를 둔다.

#### comments — 댓글

| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| id | uuid (PK) | 댓글 ID |
| post_id | uuid (FK → posts.id) | 대상 글 |
| author_id | uuid (FK → profiles.id) | 작성자 |
| content | text, not null | 내용 (1~500자) |
| created_at | timestamptz | 작성 시각 |

#### likes — 좋아요

| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| post_id | uuid (FK → posts.id) | 대상 글 |
| user_id | uuid (FK → profiles.id) | 좋아요한 회원 |
| created_at | timestamptz | 누른 시각 |

- PK는 `(post_id, user_id)` 조합이다. 한 회원이 한 글에 한 번만 좋아요할 수 있음을 데이터 수준에서 보장한다.
- 좋아요 취소는 해당 행을 삭제한다.

### 5.3 집계 값

- 좋아요 수, 댓글 수, 작성한 글 수는 별도 컬럼에 저장하지 않고 조회할 때 집계한다.
- 데이터가 늘어 느려지면 `posts`에 카운터 컬럼을 추가하는 방식으로 바꾼다.

### 5.4 파일 저장소 (Supabase Storage)

| 버킷 | 용도 | 읽기 | 쓰기 |
| --- | --- | --- | --- |
| avatars | 프로필 이미지 | 전체 공개 | 본인 폴더(`{user_id}/`)에만 업로드·교체·삭제 |

### 5.5 접근 권한 (RLS)

| 테이블 | 조회 | 생성 | 수정 | 삭제 |
| --- | --- | --- | --- | --- |
| profiles | 전체 | 가입 시 자동 생성 | 본인만 | 불가 |
| posts | 전체 | 회원 (작성자는 본인으로 고정) | 불가 | 불가 |
| comments | 전체 | 회원 (작성자는 본인으로 고정) | 불가 | 불가 |
| likes | 전체 | 회원 (본인 명의만) | 불가 | 본인만 |

## 6. 확인이 필요한 가정

요청에 명시되지 않아 아래와 같이 가정하고 작성했다. 결정이 달라지면 해당 절을 고친다.

| # | 가정 | 영향 범위 |
| --- | --- | --- |
| 1 | 비회원도 글·댓글·프로필을 읽을 수 있고, 쓰기 동작만 로그인이 필요하다 | 0.2, 전체 접근 권한 |
| 2 | 가입 수단은 이메일·비밀번호뿐이며, 이메일 인증 없이 가입 즉시 로그인된다 | AUTH-01 |
| 3 | 글은 제목과 본문 텍스트로만 구성한다 (이미지 첨부 없음) | POST-01, posts 테이블 |
| 4 | 글·댓글의 수정과 삭제는 만들지 않는다 (요청 기능에 없음) | 0.3, 5.5 |
| 5 | 댓글은 한 단계만 지원하고, 좋아요는 글에만 있다 | CMT-01, LIKE-01 |
| 6 | 좋아요 버튼은 글 상세에만 두고, 피드에는 숫자만 표시한다 | LIKE-01, POST-02 |
| 7 | 글 작성은 홈 화면의 플로팅 버튼으로 진입한다 (탭이 3개로 고정이므로) | POST-01, S-01 |
| 8 | 설정 탭에는 계정 이메일, 로그아웃, 앱 버전만 둔다 | SET-01 |
| 9 | 하단 탭은 탭의 첫 화면 3곳에만 표시한다 | NAV-01 |
| 10 | 글자 수·파일 용량·페이지 크기 등 수치는 임시값이다 | 2장 전반 |
